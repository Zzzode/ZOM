# ZOM Compiler Plan - 2026 Q4 (October - December)

> Planning window: **2026-10-01 to 2026-12-31**.
> Authored: 2026-08-25 (during Q3). Owner: compiler team.
> Scope: one quarter. Prior and subsequent quarters live in sibling files under
> `docs/plan/` (e.g. `2027-q1.md`). This document is the committed plan for Q4
> only; revise it in place during the quarter and archive it unchanged after.
>
> This plan is anchored to two hard constraints: (1) the RFC governance
> dependency chain (a status transition must precede any implementation it
> gates), and (2) on-disk technical reality verified against the source tree as
> of 2026-08-25, not aspiration. Every item is classified **reachable now**,
> **spec-blocked**, or **governance-blocked** so no work begins that a
> prerequisite forbids.

## Entry state (as of 2026-08-25, verified)

The frontend pipeline runs end-to-end:

```
Lexer -> Parser -> Binder -> Checker -> CheckedModule -> HIR -> Built MIR
```

- Built MIR emits `Return`, `Unreachable`, `Call`, `Goto` (0x04), `SwitchInt`
  (0x05) terminators and a `Comparison` (0x03) rvalue.
- Lowered shapes today: scalar local writes/transfers, nominal aggregate init
  and field writes, same-module direct calls with scalar-literal or parameter
  arguments, four-block diamond conditionals (primitive relational comparisons
  `Eq/Ne/Lt/Le/Gt/Ge` over two scalar operands, each a parameter or scalar
  literal), returned comparison results, and a minimal reducible `while` loop.
- Ownership rail (RFC 0007/0013) runs fail-closed; general region liveness,
  escape/capture production, and verified typestate remain in progress.
- **No backend:** no target LIR, ABI lowering, LLVM IR, object emission, or
  linking. ZOM cannot yet produce a native binary.

## Dependency chain (the spine)

```
RFC 0016 (REVIEW) --> RFC 0021 (DRAFT) --> LIR/LLVM backend --> native binary
                                     \--> RFC 0043 (link + executable)
RFC 0006 error-union type --> RFC 0046 (panic ABI) --> error-operator lowering
```

## Q4 goals (what "done" means by 2026-12-31)

- **G1.** Primitive arithmetic and bitwise binary operations lower end-to-end
  (frontend, reachable now). **DONE** (`2ed20c94`).
- **G2.** Multi-statement function bodies with sequential local dataflow lower
  end-to-end (frontend, reachable now). **DONE** (`3f7f5189`, `76eaa630`).
- **G3.** RFC 0016 advances from REVIEW to ACCEPTED, unblocking backend review
  (governance). **IN REVIEW** - a per-owner review guide is on record
  (`941faa2c`); the REVIEW->ACCEPTED decision is a required-owner approval and
  is not something implementation work can complete.
- **G4.** RFC 0021 enters formal REVIEW once G3 lands (governance). **BLOCKED on
  G3.**
- **Stretch.** RFC 0006 error-union type representation slice begins (spec work),
  enabling error-operator progress in a later quarter. **NOT STARTED.**

## Month-by-month

### October 2026 - frontend arithmetic + governance kickoff
- **G1:** implement primitive arithmetic/bitwise binary rvalue in MIR (new
  non-comparison binary rvalue + canonical-encoder byte with byte-oracle and
  mutation coverage), checker fact production, HIR node, and admission. Follow
  the verified comparison-operator pattern.
- **G3 (start):** open the RFC 0016 review workstream; collect reviewer feedback
  and resolve open questions. Governance, runs in parallel with G1.

### November 2026 - multi-statement bodies + RFC 0016 to ACCEPTED
- **G2:** widen surface admission beyond single-return/single-loop shapes to
  sequential statements plus local dataflow; extend HIR/MIR lowering and the
  ownership init fixpoint to cover the new shapes. Highest-leverage frontend
  unlock; largest single item this quarter.
- **G3 (land):** drive RFC 0016 to ACCEPTED with the required owner approvals.
  This is the backend master gate.

### December 2026 - backend review kickoff + spec groundwork
- **G4:** with RFC 0016 ACCEPTED, move RFC 0021 (target-aware LIR / LLVM) into
  formal REVIEW; begin RFC 0043 (link + executable) review in parallel.
- **Stretch:** start the RFC 0006 error-union type representation slice in the
  semantic type system (no error-union `TypeData` variant exists today; this is
  the prerequisite for any error-operator fact production or lowering).
- Quarter close: verify all landed frontend increments under the sanitizer
  preset, refresh the RFC 0007 tracker and `AGENTS.md` gap notes, and draft the
  2027 Q1 plan.

## Explicitly out of scope for Q4 (and why)

- **LIR/LLVM backend implementation.** Governance-blocked until RFC 0021 is
  ACCEPTED (targeted for REVIEW only this quarter). Q4 unblocks it; it does not
  build it.
- **Error-operator lowering (`?!` / `!!`) and RFC 0046 panic ABI.**
  Spec-blocked: no error-union semantic type exists and raises-carrying calls
  are rejected before an operand type exists, so no checker-only increment is
  reachable. RFC 0046 is DRAFT with no approvers. Only the RFC 0006 type slice
  (stretch) is in scope.
- **A3 drop materialization.** No MIR drop statement kind and no LIR/backend
  consumer; adding one now violates fail-closed. Deferred until the backend
  exists.
- **`as!` forced cast.** No parser support and no lowering target; adding it now
  is spec drift.

## Constraints this plan respects

- No forward compatibility, no version-suffixed contracts, fail-closed on
  unimplemented slices (`.codex/rules/design-principles.md`).
- No blocked IR or runtime artifact is published before its RFC authorizes it.
- Governance transitions are never fabricated; a DRAFT/REVIEW RFC is a real
  blocker, not a formality to route around.

## Follow-up work (beyond this quarter's committed goals)

Ordered by dependency. Frontend items are reachable now and continue the
verified fixed-shape-generalization pattern; the rest track the governance and
backend spine.

### Frontend, reachable now (no governance transition)
- **Nested / non-parameter arithmetic operands.** Comparison and arithmetic
  operands are a parameter/local reference or a scalar literal today. A nested
  binary operand (`a + b * c`) needs the checker and HIR to lower a binary whose
  operand is itself a binary node.
- **Conditional and loop bodies beyond the single admitted shape.** Conditionals
  admit two return arms; loops admit only an empty-body `while (param) {}`. Widen
  to a loop body that mutates locals (the ownership init fixpoint already handles
  the back edge; the gap is producer-side MIR lowering).
- **Local mutation across statements (`x = expr;` reassignment).** The mut-local
  scalar-write shape exists; generalize it alongside the sequential-local shape.
- **RFC 0022 flow-sensitive type refinement / null safety** (status REVIEW). A
  large checker workstream once it advances to ACCEPTED.
- **RFC 0009 dispatch widening.** Multi-argument calls, method dispatch, and
  generic-call lowering.

### Governance / spec (cannot be completed by implementation alone)
- **G3 completion:** required-owner approval of RFC 0016 snapshot
  `e421dc3b...`, then the REVIEW->ACCEPTED transition. Resolve the open question
  the review guide surfaced (`.agents/subagents` vs `.codex/subagents` in
  Repository Impact).
- **G4:** move RFC 0021 (target-aware LIR / LLVM) into REVIEW after G3; begin
  RFC 0043 (link + executable) review in parallel.
- **RFC 0006 error-union type slice (Stretch):** add an error-union
  representation to the semantic type system - the prerequisite for any
  error-operator (`?!` / `!!`) fact production or lowering, and for RFC 0046.

### Backend (next major milestone, governance-gated by G3/G4)
- **LIR + LLVM backend (RFC 0010 / 0021):** MIR -> LIR legalization, ABI
  lowering, LLVM IR generation, object emission, and linking. First point at
  which ZOM produces a native binary. Blocked on the backend RFCs reaching
  ACCEPTED, not on frontend readiness.
- **A3 drop materialization.** Add a MIR drop statement once a LIR/backend
  consumer exists; deferred until then to stay fail-closed.

### Tooling (largely independent of the backend spine)
- **RFC 0044 formatter** (DRAFT) - easiest to start early.
- **RFC 0023 IDE / LSP** (REVIEW).
- **RFC 0045 debugger** (DRAFT) - depends on backend native output.
